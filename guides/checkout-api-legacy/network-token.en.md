# Network Tokens

Card networks offer the Network Tokens service, which replaces the actual card number with a token (called DPAN) for online purchases. This token functions like a standard card with 16 digits and an expiration date but without exposing the customer's real data.

In addition to enhanced security, using Network Tokens can increase authorization rates for purchases and enable automatic updates of card details when the card expires or is replaced.

## Create card token

The process for creating a payment with Network Tokens follows the same principles as the traditional card payment flow. Instead of the actual card data, the Network Token's number and expiration date must be provided to generate the `card_token`.

Additionally, it is mandatory to include the tokenization object in the request, containing specific data provided by the network to authenticate the tokenization.

Below is an example of how to create a card token:

```curl
curl --location 'https://api.mercadopago.com/v1/card_tokens?public_key={{public_key}}' \
--header 'Content-Type: application/json' \
--data '{ 
  "card_number":"5031433215406351",
  "expiration_month": 11,
  "expiration_year": 2025,
  "security_code": "123",
  "cardholder": {
    "identification": {
      "number":"12345678910",
      "type":"CPF"
    },
    "name":"Juan Doe"
  },
    "tokenization": {
        "par": "111111XX11XXXXX1X1XXX11X1X1XX",
        "data": "XXX8xXXXXxxXXXxxXxxXXXXXXX==",
        "token_requestor_id": "XXXXXXXXXXXXXX"
        "data_type": "UCAF"
    }
}
```

The table below describes each parameter and its possible values:

| **Parameter**                          | **Type**  | **Values**                 | **Description**                                                                                                                             | **Required**                                 |
|----------------------------------------|-----------|-----------------------------|---------------------------------------------------------------------------------------------------------------------------------------------|---------------------------------------------|
| `card_number`                          | string    | Numeric                    | Network token number (DPAN) provided by the network. Replaces the actual card number to ensure more secure transactions.                    | Required                                    |
| `expiration_month`                     | int       | M                           | Expiration month of the generated card, representing the original card in digital transactions. Use values without adding a leading zero.    | Required                                    |
| `expiration_year`                      | int       | YYYY                        | Expiration year of the network token.                                                                                                       | Required                                    |
| `security_code`                        | string    | 3 or 4 digits               | Security code (CVV). Optional when using Network Tokens.                                                                                    | Optional when using Network Tokens.         |
| `card.cardholder.identification.number`| string    | Numeric                    | Cardholder's identification document (e.g., CPF, CNPJ, CI, or DNI).                                                                        | Required                                    |
| `card.cardholder.identification.type`  | string    | CPF, CNPJ, CI, or DNI       | Type of the provided document (e.g., CPF, DNI, CI).                                                                                         | Required                                    |
| `card.cardholder.identification.name`  | string    | Letters only                | Full name of the cardholder.                                                                                                                | Required                                    |
| `tokenization.data`                    | string    | Base64 string (cryptogram)  | Single-use cryptogram generated by the card network for each transaction.                                                                   | Required                                    |
| `tokenization.par`                     | string    | Alphanumeric                | Unique identifier of a card (Primary Account Reference).                                                                                    | Required                                    |
| `tokenization.token_requestor_id`      | string    | Alphanumeric (by network)   | Identifier of the merchant requesting the token. The value varies by network, and the same merchant may have different TRIDs for each network. | Required                                    |
| `tokenization.data_type`               | string    | Data content follows the UCAF format | Specifies the format of the `tokenization.data` field, as defined by the networks. Currently, only the "UCAF" format is accepted.            | Required                                    |

## Create Payment

Creating a payment with a Network Token follows the same flow as a conventional card transaction, whether for one-time or recurring payments.

To do this, the **card token** generated in the previous step must be sent along with the **payment data**.

Below is an example of the request:

```curl
curl -X POST \
   -H 'accept: application/json' \
   -H 'content-type: application/json' \
   -H 'Authorization: Bearer YOUR_ACCESS_TOKEN' \
   -H 'X-Idempotency-Key: SOME_UNIQUE_VALUE' \
   'https://api.mercadopago.com/v1/payments' \
   -d '{
    "payer": {
        "email": "test@gmail.com"
    },
    "additional_info": {
        "items": [
            {
                "quantity": 1,
                "category_id": 1234,
                "title": "My item",
                "unit_price": 10
            }
        ]
    },
    "payment_method_id": "master",
    "marketplace": "NONE",
    "installments": 1,
    "transaction_amount": 10,
    "description": "Test",
    "token": "8c054cca66ff2f0ba9d4e7724c21106f",
    "capture": false,
    "binary_mode": false
}
```

>
> The responses and statuses of a transaction processed with Network Tokens follow the same standards as a conventional card transaction in the ----[mlb]---- Checkout Transparente------------ ----[mla, mlm, mlu, mco, mlc, mpe]---- Checkout API ------------. ## Test Integration

Testing the integration with Network Tokens involves creating a test payment using predefined data.

To process a payment with Network Tokens, test cards must be used, generating random data during tokenization. The goal is to validate whether the payment is processed correctly, ensuring the integration works as expected.

When simulating different payment outcomes, enter the desired status in the `card_holder_name` field. For details on how to complete this field correctly, refer to the [test cards documentation](/developers/en/docs/checkout-api/integration-test/test-cards).

As the tests are performed with simulated responses, the data in the `tokenization` block does not need to be real but must adhere to the formats expected by the API.

Below are the requirements for each field:

| **Field**            | **Description**                          | **Example**             | **Character Limit**      |
|-----------------------|------------------------------------------|-------------------------|---------------------------|
| `par`                | Card identifier (simulated)              | 1111XX22XX33           | Up to 29 characters       |
| `data`               | Encrypted data (simulated)               | XXX8xXXXXxxXXX==       | Up to 100 characters      |
| `token_requestor_id` | Identifies the merchant that generated the token | 12345678901            | Between 11 and 15 characters |
| `data_type`          | Type of data sent                        | UCAF                   | Exactly 4 characters      |

Example:

```json
 "tokenization": {
        "par": "111111XX11XXXXX1X1XXX11X1X1XX",
        "data": "XXX8xXXXXxxXXXxxXxxXXXXXXX==",
        "token_requestor_id": "XXXXXXXXXXXXXX"
        "data_type": "UCAF"
    }
```
